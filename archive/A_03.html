Building a Reproducible Framework for Accounting Bias Research

Gianmarco Corradini, 03.08.2026

Introduction

The Accounting Bias Framework studies how recognition rules, measurement conventions, timing differences and accounting estimates can create systematic differences between reported accounting values and underlying economic values.

The empirical objective is not to observe economic value directly. In most cases, that is impossible. Instead, the methodology identifies observable financial-statement variables that represent accounting mechanisms likely to produce such differences.

The complete analysis is designed as a reproducible Python project using publicly available SEC financial-statement data.

Data Source

The project uses the SEC Company Facts database, which provides structured financial-statement information reported through XBRL.

Each observation includes information such as:

  • the company identifier;
  • the accounting concept;
  • the reported value;
  • the reporting period;
  • the filing form;
  • the filing date;
  • the accession number.

The use of standardized XBRL concepts makes it possible to extract accounting variables automatically rather than collecting them manually from annual reports.

The Processing Pipeline

The empirical workflow is divided into separate stages:

  1. download SEC Company Facts files;
  2. extract relevant accounting concepts;
  3. resolve alternative XBRL tags;
  4. construct one observation for each firm and fiscal year;
  5. calculate accounting ratios;
  6. standardize the variables;
  7. perform statistical diagnostics;
  8. export tables and figures.

Each stage produces intermediate files. This allows the researcher to inspect the data before continuing to the next step.

Extracting Accounting Variables

The software maps theoretical concepts to standardized XBRL tags. Examples include total assets, goodwill, research and development expenditure, property, plant and equipment, accumulated depreciation, receivables and deferred taxes.

Companies do not always use the same taxonomy element for economically similar items. The extraction process therefore uses an ordered hierarchy:

  1. search for the preferred tag;
  2. search predefined fallback tags;
  3. record the exact tag used;
  4. leave the value missing when no suitable fact exists.

Missing values are not automatically replaced with zero because the absence of a structured fact does not necessarily mean that the economic item is absent.

Constructing Accounting Bias Proxies

Raw accounting values are converted into ratios so that firms of different sizes can be compared.

For example, research and development intensity can be represented as:

R&D Intensity = R&D Expense / Total Assets

The relative age of property, plant and equipment can be approximated as:

PPE Age = Accumulated Depreciation / Gross Property, Plant and Equipment

Deferred-tax intensity can be represented as:

Deferred-Tax Intensity = (Deferred Tax Assets + Deferred Tax Liabilities) / Total Assets

These variables are not direct measurements of Accounting Bias. They are empirical proxies for accounting mechanisms associated with recognition, measurement, timing or estimation differences.

Data Cleaning

Before analysis, the pipeline applies several automated controls:

  • annual filings are separated from quarterly filings;
  • amended filings replace earlier versions;
  • duplicate firm-year observations are removed;
  • units and reporting periods are checked;
  • missing values are documented;
  • the original XBRL tag and filing accession number are preserved.

These controls make every transformed value traceable to its original SEC filing.

Winsorization and Standardization

Financial-statement ratios often contain extreme observations. To reduce their influence, variables can be winsorized within each fiscal year.

The cleaned variables are then converted into z-scores:

z = (x − mean) / standard deviation

Standardization places variables with different units and scales on a comparable basis.

When a variable has an inverse theoretical interpretation, its standardized value can be multiplied by minus one so that all variables follow a common direction.

Statistical Analysis

The first statistical objective is to examine the structure of the proposed variables rather than immediately estimate a predictive model.

The diagnostic workflow includes:

  • descriptive statistics;
  • histograms and boxplots;
  • Pearson correlations;
  • Spearman correlations;
  • Cronbach's alpha;
  • the Kaiser-Meyer-Olkin statistic;
  • Principal Component Analysis;
  • cluster analysis.

Internal Consistency

Cronbach's alpha evaluates whether several variables behave like interchangeable indicators of one underlying construct.

This test must be interpreted cautiously. Recognition, measurement and estimation mechanisms may contribute to a broader Accounting Bias Framework without being strongly correlated.

A low alpha may therefore indicate that the framework is multidimensional rather than statistically invalid.

Principal Component Analysis

Principal Component Analysis identifies combinations of variables that explain the largest proportion of variation in the dataset.

If one component dominates, a single composite index may be defensible. If several components remain important, separate dimensions such as Recognition Bias, Measurement Bias and Timing Bias may be more appropriate.

PCA is therefore used as an exploratory tool rather than as automatic proof of a particular theoretical structure.

Composite Measures

A simple exploratory index can be calculated as the mean of standardized components:

ABI = (z1 + z2 + ... + zk) / k

The number of available components is recorded for each firm-year. An observation is retained only when a minimum number of components is available.

Equal weighting provides a transparent baseline. Alternative versions may use theoretical weights, principal-component weights or separate sub-indices.

Software Structure

The research code is organized into independent modules for:

  • data acquisition;
  • XBRL extraction;
  • variable construction;
  • statistical diagnostics;
  • figure generation;
  • LaTeX table generation;
  • logging.
accounting_bias/
├── config/
├── data/
│   ├── raw/
│   └── processed/
├── outputs/
│   ├── tables/
│   ├── figures/
│   └── logs/
├── scripts/
├── src/
└── tests/

The modular structure allows individual variables, statistical methods or data sources to be changed without rewriting the entire project.

Automatic Output Generation

The pipeline automatically generates:

  • processed datasets;
  • coverage reports;
  • CSV tables;
  • LaTeX tables;
  • PDF figures;
  • diagnostic logs.

The manuscript can import the generated LaTeX tables and PDF figures directly. Updating the analysis therefore requires rerunning the code rather than manually editing results.

Conclusion

The empirical methodology is designed to translate a theoretical accounting framework into a transparent and testable research process.

Its main principles are simple: use public data, preserve the original source of every value, document missing information, separate data processing from statistical analysis, and generate all research outputs automatically.

The purpose is not to produce one immutable Accounting Bias formula. It is to create a reproducible framework that can be tested, criticized and extended as new variables and datasets become available.
